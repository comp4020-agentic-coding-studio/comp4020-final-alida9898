# Splitting agents by responsibility

Whether coding work should be split across several agents is one of the more contested questions in agentic development right now. Some practitioners treat a team of agents as the obvious next step, and others argue it makes systems fragile. My position is that the failures the critics describe are real, but they come from splitting one task into pieces. When the work is instead split by responsibility, with the shared decisions made in a plan before anything is handed out, each agent given a written boundary, and the results checked by someone who did not build them, a multi-agent setup holds up. Its value is in that division of ownership and independent checking rather than in doing things in parallel.

The strongest case against comes from Walden Yan at Cognition (2025). His example is a Flappy Bird clone divided between two subagents, one building the background and pipes and the other building the bird. Neither can see what the other assumed, so each fills the gaps in its brief with its own guesses and the two halves do not fit together. He sums this up as "Actions carry implicit decisions, and conflicting decisions carry bad results." Anthropic's account of its own multi-agent research system adds a cost argument: such systems use "about 15× more tokens than chats", and "most coding tasks involve fewer truly parallelizable tasks than research" (Hadfield et al., 2025). Both sources have something to sell. Cognition builds a single-agent coding product, and Anthropic is paid by the token, so neither is a neutral observer. Even so, I think Yan's example is fair as far as it goes. The bird and the pipes share one screen and one art style, so they were never independent pieces of work. They were one task cut in half, and it is not surprising that the halves disagreed.

My own project, a multi-user 3D clay town, shows a different kind of split. It began as a single long conversation, and by crit 9 everything "went through one conversation in a straight line" and had become hard to manage. I then wrote a CLAUDE.md and set up fixed roles (9e3c438): one agent owns camera views, one owns the 3D models, one owns the interface text, and one only checks. Later I stopped the main session from editing code at all. It now writes back its understanding of a request, waits for me to agree, and only then dispatches the work (217558b). In the terms of Schluntz and Zhang (2024), the roles are a form of sectioning, "breaking a task into independent subtasks run in parallel", while the main session acts as an orchestrator that decides each time which roles a request needs. The shape of a model and the camera angle that frames it really are separate jobs, so the agents I ran at the same time were ones whose work could not overlap. Anthropic seems to have arrived at the same rule through experience. Vague instructions led their subagents to duplicate each other and misread tasks, so each subagent now receives "an objective, an output format, guidance on the tools and sources to use, and clear task boundaries" (Hadfield et al., 2025). My CLAUDE.md table records much the same things for each agent: what it owns, what it hands back, and what it must not touch. Because decisions like the art style are settled in the plan and the rules first, no subagent has to guess them.

This position has limits. My boundaries were not right at the start. Seasonal weather effects and blanket colours were built before any agent was responsible for them, and only afterwards did I add a season agent and redraw the line so that the model agent builds seasonal props and the season agent only changes colours (525e58d). Yan's problem therefore still appears at the edges between roles, which is why the main session keeps the whole picture and a separate checker reviews work it did not write. Some judgements are beyond any checker, though. Anthropic notes that "even in a world of automated evaluations, manual testing remains essential" (Hadfield et al., 2025), but in my experience some things are not merely missed by automation, they cannot be judged by it at all. My rules require the checker to say when a question is about sound, feel or taste, and send spatial adjustments to an editor I use myself rather than describing them to an agent. The cat in my town is the clearest case. Agents rebuilt it several times without getting it right, and it was only fixed when I tuned it myself with sliders and the resulting numbers were copied into the code unchanged (96f789a).

When Yan wrote in June 2025, Claude Code's subagents only answered well-defined questions and did not write code. In my project they write code, and some of them run at once. What made that workable was not adding more agents but settling shared decisions early, giving each agent a clear boundary, having its work checked independently, and leaving questions of taste to a person.
